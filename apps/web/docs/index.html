Quickstart

You need Node.js 20 or newer. The deterministic fixture mode needs no API key.

  1. Clone and install
    Dependencies are locked in package-lock.json.
    shell
    git clone https://github.com/HazEOskA/osa-proof.git
cd osa-proof
git checkout a321fd2   # until PR #2 fixes main
npm ci
  2. Run the tests
    Builds TypeScript and runs the node test suite: 44 pass, 1 live-provider test skipped.
    shell
    npm test
  3. Start the API in fixture mode
    OSA_EXECUTION_MODE is required. There is no default: a missing or unknown value refuses to start.
    shell
    npm run build
OSA_EXECUTION_MODE=fixture PORT=3000 node dist/apps/api/src/server.js
  4. Switch to a real model
    Provider mode calls Anthropic behind the ModelProvider interface. Missing provider, model or key refuses to start.
    shell
    OSA_EXECUTION_MODE=provider \
OSA_PROVIDER=anthropic \
OSA_MODEL=<model id> \
ANTHROPIC_API_KEY=<secret> \
node dist/apps/api/src/server.js

Your first mission

Register a two-agent Team Graph, submit a mission with one acceptance requirement, run it, and read the receipt. The server decides which implementation serves dev.planner.v1 and dev.builder.v1.

1. Register the team

POST /teams
curl -s localhost:3000/teams -H 'content-type: application/json' -d '{
  "organization_id": "org_dev", "project_id": "project_dev", "team_id": "team_dev", "version": "1",
  "agents": [
    { "agent_id": "planner", "role": "planner", "executor_ref": "dev.planner.v1" },
    { "agent_id": "builder", "role": "builder", "executor_ref": "dev.builder.v1" }
  ],
  "edges": [{ "edge_id": "planner_to_builder", "from_agent_id": "planner", "to_agent_id": "builder", "kind": "handoff" }]
}'

2. Submit the mission

POST /missions
curl -s localhost:3000/missions -H 'content-type: application/json' -d '{
  "organization_id": "org_dev", "project_id": "project_dev", "mission_id": "mission_hello",
  "team_id": "team_dev", "team_version": "1", "entry_agent_id": "planner",
  "objective": "Write landing page copy", "input": { "request": "Write landing page copy" },
  "requirements": [{ "requirement_id": "artifact_status", "type": "evidence_field_equals",
    "evidence_kind": "artifact", "agent_id": "builder", "field": "status", "expected": "built" }]
}'

3. Run it and read the proof

POST /missions/:id/run · GET /runs/:id/proof
RUN=$(curl -s -X POST localhost:3000/missions/mission_hello/run | node -pe 'JSON.parse(require("fs").readFileSync(0)).run_id')
curl -s localhost:3000/runs/$RUN/proof

Core concepts

Every surface compiles to the same Team Graph. Everything after that exists to turn a run into evidence and evidence into a verdict.

Canonical state

Team Graph

Agents, their executor refs and the edges between them. Validated before every run. Today: linear handoff.

packages/team-graph
Intent

Mission

An objective, an input and explicit acceptance requirements. A mission without requirements is rejected.

packages/contracts
Execution

Runtime and executors

Walks the graph and calls each executor through the ExecutorRegistry. Providers sit behind ModelProvider.

packages/runtime · packages/adapters
Evidence

Evidence records

Bound to one execution. Core computes evidence_sha256 and content digests; executor hashes are claims.

packages/evidence
Decision

Deterministic verifier

Checks binding and digests, records verifier observations, then evaluates requirements over evidence that passed.

packages/proof-core
Output

Proof receipt

Sealed after the final verdict: proof_id commits to the verdict, evidence root and final output.

packages/proof-core

How a run is proven

Six stages, in order. A runtime failure is an input to the verifier, so it can never produce VERIFIED.

01Team Graphvalidated
02Missionrequirements set
03Runtimeexecution_id bound
04Evidencehashed by core
05Verifierobserves, decides
06Receiptsealed

VerdictWhen
VerifiedEvery requirement is met by evidence that passed binding and digest checks, and the runtime did not fail.
FailedEvidence contradicts a requirement, fails an integrity check, or the runtime failed.
IncompleteThe evidence a requirement needs was never produced.

Configuration

Everything is read from the environment. Secrets never reach events, evidence, receipts, logs or error messages.

VariableRequiredDefaultMeaning
OSA_EXECUTION_MODEAlwaysnonefixture or provider. Anything else refuses to start.
OSA_PROVIDERProvider modenoneanthropic or openai
OSA_MODELProvider modenoneModel id sent to the provider.
ANTHROPIC_API_KEY · OPENAI_API_KEYProvider modenoneSecret of the selected provider.
OSA_PROVIDER_BASE_URLNohttps://api.anthropic.comPoint at a stub or proxy.
OSA_PROVIDER_TIMEOUT_MSNo120000Per-call timeout; a timeout fails the run.
OSA_PROVIDER_MAX_TOKENSNo16000Output token cap per call.
OSA_PROVIDER_MAX_RETRIESNo2Retries for connection errors, timeouts, 408, 409, 429 and 5xx (0 to 10).
OSA_MODEL_FALLBACKSNononeOrdered provider:model fallbacks (max 4) tried after the primary fails; every hop is evidence.
OSA_PROVIDER_RETRY_BASE_MSNo500First backoff step; doubles per retry up to 8 s. retry-after wins.
PORT · HOSTNo3000 · 0.0.0.0Where the API listens.
OSA_LIVE_PROVIDER_TESTNooffSet to 1 to run the live provider test.

HTTP API

JSON in, JSON out. State is held in memory by the API process. Errors return {"error": "…"} with 400, 401, 404 or 409. Teams, missions, runs and run evaluations need a DEV session: POST /auth/dev-login, then Authorization: Bearer <token>. OAuth providers are not configured.
